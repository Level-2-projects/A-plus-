# PROJECT CONTEXT

> "A Plus" (A+) is a web LMS for a college Software Engineering course project. Plain HTML, CSS, vanilla JS (ES modules), no frameworks or build tools. Planned backend (NOT started): FastAPI + SQL Server. n8n comes LAST (real AI feedback, absence warnings, weekly summary, a reminder a day before deadlines). Pilot: about 40 students, 6 doctors, the dean.
>
> Roles: super_admin (the dean: reads and analyzes the whole college, creates departments and their admins, announcements, settings), department_admin (own department only: students, doctors, courses, enrollments, monitoring, messages), doctor, student. Accounts are created by admins; there is no self-registration.
>
> Product decisions: a student submits an assignment ONCE and gets instant AI feedback with NO score; the AI also produces an opinion score out of 10 visible ONLY to the doctor; only the doctor sets the final grade; attendance is shown per course; points are a raw total that resets monthly with a monthly top 3 per department (doctors can award bonus points); doctors send notices, warnings and suggestions that arrive in an inbox like an email; students may rate lectures and doctors (optional, anonymous to the doctor); to-do list; Roadmaps (logic PROVISIONAL). There is NO chatbot page anywhere.
>
> Architecture: the front end runs on a shared localStorage mock. One request() in js/core/http.js; when USE_MOCK is true it calls js/mock/mock-server.js (router, possibly split into js/mock/routes/*), which uses js/mock/mock-db.js (key aplus_mock_db, seed in js/mock/seed/*.js, resetToSeed), js/core/clock.js (getNow and a fake clock for tests) and settings stored in the database. API modules js/api/{student,doctor,admin,dean}-api.js only call request(). Status codes: 401, 403 (wrong role or out of scope), 404, 409, 422, 429. Switching USE_MOCK to false later must change nothing in the pages. Role homes (ROLE_ROUTES): student /student/dashboard.html, doctor /doctor/dashboard.html, department_admin /department-admin/dashboard.html, super_admin /super-admin/overview.html. Tests: js/dev/test-scenarios.js, run with `node dev/node-test-runner.mjs` or dev/test-runner.html. Dev tools: dev/mock-playground.html. Docs: docs/PROGRESS.md, api-contract.md, data-model.md, manual-test-guide.md, README.md.
>
> Known seed accounts (verify in js/mock/seed/users.js): doctor@aplus.edu / Doctor123, doctor2@aplus.edu / Doctor2!, student@aplus.edu / Student123, student2..student5@aplus.edu / Student2!..Student5!, dept@aplus.edu / Dept123, dean@aplus.edu / Dean123, disabled@aplus.edu / Disabled123 (login rejected with 403); a second department (Information Systems) with its own admin was added: record its accounts.
>
> Known history: an agent once wrote "all tests pass" without running them; another pasted a huge block twice and broke the whole site; mock-server.js grew to thousands of lines. Always paste real runner output, keep files small, never run two agents on the same files, back up before big steps. Possible leftovers: an older copy of the project in a sibling folder named "A plus" (do not touch it), and a stray 0-byte file named A.
>
> Coding standards (every file): header comment (purpose, imports, exports); a comment on every section and function explaining what and why; JSDoc on exports; one responsibility per file; descriptive kebab-case names (no utils.js or helpers.js); no magic values (config constants); no inline styles or handlers; no globals; all user-facing text in js/config/strings.js; explicit error handling; semantic accessible HTML; reuse before creating; no duplicated code; update comments when code changes; no dead code or stray console.log.
>
> Design rules (do not redesign the shell): tokens only from css/tokens.css (navy #0F2A4D, primary #1F4B7F, secondary #2F80C4, aqua #27A7C4, gold #D4A72C, background #E8F0F8 with two soft glows); fonts Plus Jakarta Sans (headings, big numbers), Inter (body), Montserrat (login heading only), Source Serif 4 bold for the topbar page title via setPageTitle; tabular-nums; white sidebar with the logo, a gold divider and "Small steps, big goals"; active nav item solid primary with white text; sidebar-only soft hover #E9F1FB; solid buttons use the login lighter-blue hover; NO underline on hover anywhere; the footer shows only the user's name ("Eng. <name>" for students) linking to Profile, no hover effect; NO tinted or translucent boxes (status = solid dot + text; the only filled badge is the small solid gold unread-count circle); gold only for unread counts, points and medals; aqua for progress; green only for success; no "under construction" boxes. Shared building blocks exist (toast, dialog, tabs, data table, empty/error states, skeletons, form-error helpers, count-up, progress rings, .card, .card--hero, .card--interactive, .status, medals): reuse them. Responsive from 360px; sidebar becomes a drawer under 900px.
>
> Intended order of the remaining work: (1) split mock-server.js by role with no behavior change if not already done; (2) Stage B of the admin/dean logic: analytics (attendance rate, submission rate, average grade, average doctor rating with no student identities, at-risk counts, top 3, period filter), dean-only settings that take effect immediately, broadcasts (audiences, one unread message per recipient, admins limited to their own department and the dean), the doctor "Received" tab, the dean Inbox, scenarios up to an end-to-end four-role scenario; (3) Department Admin UI pages; (4) Dean UI pages; (5) polish, demo seed, accessibility, a full demo script; then the real backend, then n8n.
